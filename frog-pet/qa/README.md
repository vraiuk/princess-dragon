# QA Жабки

Процесс построен по рекомендациям Anthropic по проверке агентной работы ([Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices)):

1. **Сначала детерминированные проверки, потом LLM-судьи, люди — для калибровки.**
2. **Проверяем итог, а не слова.** Тест смотрит на состояние (`frog.json`, `view`, DOM, пиксели), а не на то, что агент сказал «готово».
3. **Много прогонов и чистое окружение.** Фазз гоняет 40 случайных недель, каждая из чистого состояния. E2E запускается с новым `HOME`.
4. **Проверка самой проверки.** Мутационные прогоны: ломаем код нарочно и убеждаемся, что тест падает. Тест, который не падает на поломке, ничего не стоит.
5. **Кто нашёл — тот не чинит.** Тестировщики только ищут и пишут находки с воспроизведением. Каждую находку независимо перепроверяет другой агент, и только потом её чинят. После фикса — повторный круг и регрессия.
6. **Каждый найденный баг превращается в тест**, чтобы не вернулся.

## Команды

```sh
npm test                 # юнит-тесты + фазз (40 недель, ~15 с)
FUZZ_SEED=1017 npm test  # воспроизвести конкретный прогон фазза
npm run qa:ui            # браузерные проверки интерфейса + скриншоты в qa/out
npm run qa:ui -- --film  # плюс кадры сценария съёмки
npm run qa:e2e           # настоящий Electron под xvfb (Linux) — сценарии qa/e2e/*.js
npm run qa               # всё вместе
```

## Что проверяется автоматически

| Уровень | Файл | Инварианты |
|---|---|---|
| Логика | `test/core.test.js`, `test/achievements.test.js`, `test/showcase.test.js` | пороги, смерть, возрождение, ачивки, сценарии |
| Фазз | `test/fuzz.test.js` | смерть только после предупреждения critical; не умирает, пока человек отошёл; не умирает без хардкора; нет напоминаний мёртвой или на паузе; ачивка не выдаётся дважды даже после перезапусков; значения view в [0,1]; лимиты history/кладбища; `check()` быстрее 2 мс |
| Интерфейс | `qa/ui-check.js` | без ошибок консоли; облачко и тост внутри окна и не перекрываются; fps 15–40 и мало частиц в покое; клики сквозь прозрачные места; надгробие после смерти, кнопки спрятаны; возрождение убирает частицы; окна без горизонтального скролла в светлой и тёмной теме; лендинг на 1280 и 390 px |
| Electron | `qa/e2e/*.js` через `FROG_TEST_SCRIPT` | онбординг, миграция с v1, IPC-действия, настройки и перезапуск, смерть и уведомления, окна, режим съёмки не портит сохранение, битый `frog.json` |
| CI | `.github/workflows/frog-pet.yml` | тесты, UI-проверки и e2e на Linux до сборки dmg |

## LLM-судьи: рубрика

Скриншоты из `qa/out` оценивает отдельный агент на каждое измерение. Ответ по каждому пункту: **да / нет / не знаю**, плюс доказательство (имя файла и что на нём видно). «Не знаю» лучше выдуманной оценки.

1. **Читаемость.** Текст облачка и тоста читается целиком, не обрезан, контраст достаточный на светлом и тёмном фоне.
2. **Понятность состояния.** По одному кадру понятно, что с жабой: хочет пить, каменеет, при смерти, умерла, спит, кодит.
3. **Нет визуального мусора.** Ничего не перекрывает морду жабы; нет артефактов, обрезанных частиц, «висящих» элементов после анимации.
4. **Действие очевидно.** Если жабе что-то нужно, видно, куда нажать (кнопка в облачке или сбоку).
5. **Тон.** Шутки программистские и добрые, нет грубости, нет повторов подряд, русский без ошибок.
6. **Готово к ролику.** Кадр можно поставить в шортс без стыда: композиция, жаба в кадре, ничего не дёргается.

## Формат находки

`qa/findings/<круг>-<агент>.json` — массив:

```json
{ "id": "r1-ux-03", "severity": "high|medium|low", "area": "pet|death|toast|trophies|settings|welcome|main|core|achievements|showcase|landing|packaging",
  "title": "коротко", "repro": "шаги или команда", "expected": "...", "actual": "...", "evidence": "путь к скриншоту/логу", "file": "app/...:строка" }
```
