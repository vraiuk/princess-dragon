# QA Жабки

Процесс построен по рекомендациям Anthropic по проверке агентной работы ([Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), [Best practices for Claude Code](https://code.claude.com/docs/en/best-practices)):

1. **Сначала детерминированные проверки, потом LLM-судьи, люди — для калибровки.**
2. **Проверяем итог, а не слова.** Тест смотрит на состояние (`frog.json`, `view`, DOM, пиксели), а не на то, что агент сказал «готово».
3. **Много прогонов и чистое окружение.** Фазз гоняет 40 случайных недель (в CI — 80), каждая из чистого состояния, в поясе с переводом часов. E2E запускается с новым `HOME`.
4. **Проверка самой проверки.** Мутационные прогоны: ломаем код нарочно и убеждаемся, что тест падает. Тест, который не падает на поломке, ничего не стоит.
5. **Кто нашёл — тот не чинит.** Тестировщики только ищут и пишут находки с воспроизведением. Каждую находку независимо перепроверяет другой агент, и только потом её чинят. После фикса — повторный круг и регрессия.
6. **Каждый найденный баг превращается в тест**, чтобы не вернулся.

## Команды

```sh
npm test                 # юнит-тесты + фазз (40 недель, ~15 с)
FUZZ_SEED=1017 npm test  # воспроизвести конкретный прогон фазза
FUZZ_RUNS=80 npm test    # больше недель (так в CI)
FUZZ_CORE=/tmp/core.mut.js node --test test/fuzz.test.js   # мутационная проверка фазза на сломанной копии core
FUZZ_ACH=/tmp/ach.mut.js node --test test/fuzz.test.js     # то же для achievements; FUZZ_TZ — другой пояс
QA_ROOT=/tmp/broken-copy npm run qa:ui -- --out /tmp/out  # UI-проверки на сломанной копии приложения
npm run qa:ui            # браузерные проверки интерфейса + скриншоты в qa/out
npm run qa:ui -- --film  # плюс кадры сценария съёмки
npm run qa:e2e           # настоящий Electron под xvfb (Linux) — сценарии qa/e2e/*.js
npm run qa               # всё вместе
```

## Что проверяется автоматически

| Уровень | Файл | Инварианты |
|---|---|---|
| Логика | `test/core.test.js`, `test/achievements.test.js`, `test/showcase.test.js` | пороги, смерть, возрождение, ачивки, сценарии |
| Фазз | `test/fuzz.test.js` | смерть только после *свежего* critical (ожидание сбрасывается, когда попил/размялся/ушёл/ночь опустили долю ниже зоны critical); не умирает, пока человек отошёл, и в тике после паузы ≥ breakAfter; не умирает без хардкора; нет напоминаний мёртвой или на паузе, мёртвой не говорят «камень осыпался»/«на посту»; «утро»/возрождение только после настоящих >2 ч (скачки часов назад, разовый тик из прошлого, NaN); шаги времени 20 с, 1 с, 20 с–2 ч и 2–16 ч; DST (Europe/Berlin, март и октябрь); «враждебные» настройки как из frog.json; state конечен, day.date валиден, history по порядку; ачивка не выдаётся дважды; list() согласован с выданными, прогресс в [0,max], полный прогресс = выдана, секреты замаскированы; каждая ачивка, кроме заведомо долгих, хоть раз выдаётся за 40 недель; значения view в [0,1]; лимиты history/кладбища; `check()` быстрее 2 мс |
| Интерфейс | `qa/ui-check.js` | без ошибок консоли; облачко и тост внутри окна и не перекрываются; все реплики core (включая 42 пары «разминка + совет») не обрезаны: scrollHeight ≤ clientHeight у текста и совета, кнопки целиком; fps ≤ 40, человек отошёл ≤ 10, надгробие ≤ 3, спрятанное окно — 0 кадров; мало частиц в покое; reduced motion — нет бесконечных анимаций (critical, тосты всех редкостей, надгробие); контраст кнопок облачка и окон ≥ 4.5:1; клики сквозь прозрачные места; надгробие после смерти, кнопки спрятаны; возрождение убирает частицы; окна и лендинг без горизонтального скролла и без элементов за правым краем (видно и при overflow-x:hidden) |
| Electron | `qa/e2e/*.js` через `FROG_TEST_SCRIPT` | онбординг, миграция с v1, IPC-действия, настройки и перезапуск, смерть и уведомления, окна, режим съёмки не портит сохранение, битый `frog.json` |
| CI | `.github/workflows/frog-pet.yml` | тесты (фазз 80 недель), UI-проверки и e2e на Linux до сборки dmg; `qa/out` выкладывается артефактом `frog-qa-out` даже при падении |

Мутационная проверка (круг 2): старый фазз пропускал все 5 мутантов core ниже, новый ловит все 7: нет сброса `crit.water` в `drink()`, нет сброса `crit.move` в `endSitting()`, нет ухода «по dt», нет защиты от разового тика из прошлого, смерть без critical при перепрыгивании зоны, нет защиты от NaN, секретные ачивки не замаскированы в `list()`. Новые UI-проверки падают на HEAD до фиксов круга 2 (fps, обрезка совета, reduced motion, контраст облачка) или на нарочно сломанной копии (зелёная кнопка `#3fae5a` в окнах, лендинг с `overflow-x:hidden` и элементом шире экрана).

## LLM-судьи: рубрика

Скриншоты из `qa/out` оценивает отдельный агент на каждое измерение. Ответ по каждому пункту: **да / нет / не знаю**, плюс доказательство (имя файла и что на нём видно). «Не знаю» лучше выдуманной оценки.

1. **Читаемость.** Текст облачка и тоста читается целиком, не обрезан, контраст достаточный на светлом и тёмном фоне.
2. **Понятность состояния.** По одному кадру понятно, что с жабой: хочет пить, каменеет, при смерти, умерла, спит, кодит.
3. **Нет визуального мусора.** Ничего не перекрывает морду жабы; нет артефактов, обрезанных частиц, «висящих» элементов после анимации.
4. **Действие очевидно.** Если жабе что-то нужно, видно, куда нажать (кнопка в облачке или сбоку).
5. **Тон.** Шутки программистские и добрые, нет грубости, нет повторов подряд, русский без ошибок.
6. **Готово к ролику.** Кадр можно поставить в шортс без стыда: композиция, жаба в кадре, ничего не дёргается.
